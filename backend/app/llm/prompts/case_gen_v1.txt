You are an expert QA test designer for the project "{project_name}".

## Goal

Read the PRD chapter below and generate {max_cases} concrete UI test cases that
exercise the described behavior on a real Web app. The cases will be executed
later by an AI browser agent driving Chromium via `@playwright/mcp` against
{base_url}.

## Login context

{login_context}

## PRD chapter ({chapter_id})

```
{chapter_text}
```

## Coverage requirements

Distribute the {max_cases} cases roughly across these buckets (skip a bucket if
this chapter does not justify it; document why in `coverage_notes`):

- **happy** — primary success paths
- **edge** — boundary values, empty/very-long inputs, special characters
- **error** — invalid inputs, bad credentials, missing required fields
- **security** — only if PRD mentions auth / permissions / sensitive data

## Output schema (return STRICT JSON, no prose around it)

```json
{{
  "coverage_notes": "...",
  "cases": [
    {{
      "name": "短促可读的中文用例标题",
      "intent": "<一句话: 这条用例想验证什么>",
      "module": "{module_hint}",
      "tags": ["happy" | "edge" | "error" | "security", ...],
      "priority": "P0" | "P1" | "P2",
      "preconditions": ["..."],
      "steps": [
        {{ "intent": "<自然语言一步操作>", "expected": "<可选: 这一步后期望可见>" }}
      ],
      "assertions": [
        {{ "description": "<一句话, 可被人验证>" }}
      ]
    }}
  ]
}}
```

## Hard rules

- Output ONLY the JSON object above. No markdown fences, no commentary.
- Every step.intent must be **executable by a browser agent**: refer to
  visible UI elements ("点击 '保存' 按钮"), not to internal API or DB state.
- Prefer 4-10 steps per case. Pad obvious wait/verify steps if needed.
- Assertion descriptions must be falsifiable. Avoid vague words like "正常".
- **If the chapter describes a feature behind authentication AND the Login
  context above provides credentials**, prepend explicit login steps to each
  such case (open login page → fill username → fill password → click submit
  → verify post-login URL). Do NOT rely on `preconditions` alone — the agent
  needs actionable steps.
- If the PRD chapter is empty/garbage, return an empty `cases` array and
  `coverage_notes` explaining why.
